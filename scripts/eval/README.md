# 金标检索基准（scripts/eval）

回答一个问题：**这次对 `src/search.ts` 的改动，让检索变好还是变差？**

在此之前，仓库里没有任何办法在仓库内回答它 —— 只有论文目录里的实验脚本，带着
`数据/快照_*` 这类外部路径。这里把它重写成仓库内版本：只依赖一个 `--db`（库副本）
和一个 `--dist`（构建目录），不反向依赖论文目录。

```
scripts/eval/
  queries.gold.json   69 条：{q, gold:[id…], 类别, 片段出现次数}
  run_arms.mjs        每臂一份独立库副本 → 跑查询 → 报数 → 跑门禁
  metrics.mjs         命中@k / MRR / 精确 McNemar（纯函数）
  expected.json       现行默认的期望值（hit1 0.768 / hit5 1.000 / MRR 0.857）
  README.md           本文
```

## 跑法

```bash
npm run build                                     # 被测的是 dist/，先构建

node scripts/eval/run_arms.mjs \
  --db <库根>/default \                              # 其下有 default/<角色>/<memtype>/memory.sqlite
  --project default \
  --arms default,constant,time015,emo0 \
  --embed none \                                  # 纯词法：跨机器可复现
  --out /tmp/eval.json
```

输出：

```
臂            命中@1  命中@5  命中@10  MRR    未命中
default         72.5%  100.0%  100.0%  0.833  0
constant         0.0%    0.0%    0.0%  0.000  69
time015         68.1%   94.2%   95.7%  0.790  3
emo0            75.4%  100.0%  100.0%  0.850  0
```

> 为什么这里写 72.5% 而交接报告写 76.8%：报告那次是**默认渠道**连跑 69 条，每条查询的
> 命中行被 +`accessed_count`、`last_accessed_at` 刷成现在，于是它们在后续查询里分数更高
> （accessBoost 最高 +8%、时间衰减≈1.0）。本跑器一律用 `accessChannel:'diagnostic'`，
> 查询之间不互相强化。差的那 3 条（53 vs 50）就是这个污染，不是参数效果。详见 §复现偏差。

退出码：`0` = default 不低于 `expected.json` 的命中@1 − 2pp；`1` = 低于；
`2` = 环境问题（缺构建、缺库、缺查询集）。**可以挂进 CI**，把 `--db` 指向一份
带内嵌金标的固定库副本即可（库本身不进仓库，见下）。

### 比较「改了代码常量」的两个构建

`--arms` 只能改环境变量。相似度上限（0.95）这类**编译期常量**要换构建：

```bash
git worktree add C:/tmp/base HEAD~1 && (cd C:/tmp/base && npm ci && npm run build)
node scripts/eval/run_arms.mjs --db <库> --project default --dist D:/AI/castalia/Castalia-Anima/dist --arms default
# ⚠️ --dist 必须是一个**带 node_modules 的检出内**的 dist（副本不能搬到仓库外：
#    dist/*.js 会按自身路径向上找 better-sqlite3，找不到就 ESM 解析失败）
cp -r dist .tmp-olddist && sed -i 's/, 0.95)/, 0.7)/' .tmp-olddist/search.js
node scripts/eval/run_arms.mjs --db <库> --project default --dist .tmp-olddist --arms default
```

**负控制（2026-10-31 实跑，用来证明这个门禁真的会拦）**：把 dist 里的
`0.95 → 0.7`、`WEIGHT_TIME 0.03 → 0.15`（即回退到 2026-10-28 的常量）后：

```
default         55.1%   89.9%   95.7%  0.698  3
门禁: default 命中@1 55.1% vs 期望 72.5%（下限 70.5%）→ 不通过   （退出码 1）
```

同一协议下的配对（精确 McNemar，逐条排名见 `--out` 的 `逐条` 字段）：

```
default vs 旧常量 @1：仅前者命中 0 / 仅后者 12，p=0.0005
default vs 旧常量 @5：仅前者命中 0 / 仅后者  7，p=0.0156
```

**一条查询都没变差**，12 条从「不在前 1」变成「在前 1」。这就是那两处常量值得进源码的
证据 —— 而且它是独立复现的：报告里的 53.6%/85.5% 与这里的 55.1%/89.9% 差 1~4 条，
差异同样来自 §复现偏差 说的跨查询访问强化。

## 三条纪律（都是踩出来的，不是风格偏好）

1. **每臂独立副本。** 检索会写 `memory_access_log` 与 `last_accessed_at`，共用副本会
   污染后续臂 —— 2026-10-31 因此作废过一整轮（`结果/R8a_探针污染说明.json`）。
   `run_arms.mjs` 对每个臂复制一份项目目录，跑完即删（`--keep` 保留排障）。
2. **必须同时报常数基线。** `--arms constant` 永远返回同一批 id（按 created_at 倒序
   取 topK）。任何条件化改动（状态匹配、弃权、情绪重排）都要看它的命中率 ——
   否则会把常数先验读成机制收益（R27：表面 +12.8pp，与常数负向的 Jaccard=0.982）。
3. **区分口径。** 二元符号输出不能与三分类参考直接比（R47：同一份数据、两种口径
   差 12.7pp，且非中性子集上方向会反）。

## 这份金标能说什么、不能说什么

- **能说**：权重/上限/衰减改动会不会把**正确的行**挤出前 k。
- **不能说**：线上检索效果。查询是**原文片段**，词法通道天然容易命中（命中@5 已经
  100%，天花板效应明显）。真正的难度来自「用户换了说法」，那需要改写集，而改写集
  在本仓没有（论文里那版因跨批改判被撤回）。
- **不能说**：这份数据上没有差异 = 没有差异。69 条只能判到 ~±5pp（一个不一致对
  p≈0.06）；`emo0` 与 `default` 差 1 条、p=1，正确读法是「分不出来」，不是「关掉
  情感项更好」。

## gold 的由来与可迁移性

`queries.gold.json` 的 `gold` 是**某一份快照里的行 id**（见 `_meta.源库sha256`），
只对同一份快照成立：

- 快照：`副本_SMP输入端_20261031070833`（default 项目，197 行，211 个候选片段）
- 造法（论文侧）：取活跃行的原文片段当查询，`gold` = 包含该片段的**所有**活跃行 id；
  60 条单 gold、9 条双 gold。
- **换库就要重造**：行 id 会变。重造的最小步骤是「随机取活跃行的一个片段 → 用
  `LIKE '%片段%'` 收回所有包含它的活跃行 → 记成 `{q, gold}`」，并保证片段长度足够
  （太短的片段会命中半库）。造完跟一次 `--arms constant`，它必须接近 0；不是 0 说明
  gold 太宽。

## 复现偏差（记录，不掩盖）

交接报告的数字是 **default=76.8%、time015=68.1%**；本跑器实测 **72.5% / 68.1%**。
差异来源已定位，不是噪声：

| 项 | 报告 | 本跑器 | 原因 |
|---|---:|---:|---|
| default 命中@1 | 76.8%（53/69） | 72.5%（50/69） | 报告那轮按默认渠道连跑，命中行被 +`accessed_count`、`last_accessed_at` 刷成现在 → 在后续查询里分数更高（accessBoost ≤+8%、时间衰减≈1）。本跑器用 `accessChannel:'diagnostic'`，查询相互独立 |
| time015 命中@1 | 68.1% | 68.1% | 一致 |

也就是说：**76.8% 里有 3 条是跨查询访问强化撑出来的**。这本身是个可用结论（线上真实
使用也会有这种正反馈），但它不是「权重/上限改得好」的证据，所以基准一律关掉它。
要复现报告的 76.8%：把 `run_arms.mjs` 子进程里的 `accessChannel` 去掉即可。

门禁只用 `default`（72.5%），对照臂的数字只作参考、不进门禁。
