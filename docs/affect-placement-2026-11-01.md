# 情感信号的位置：三个候选层，两份实测（2026-11-01）

**问题**：情感（VAD / 情绪强度）应该放在系统的哪一层？
候选：① 检索打分（现状）② 注入决策（要不要注入这条）③ 提示词状态块。

**结论先说**：现状那一层（检索打分）**测不出任何效应**；放大权重则**显著变差**；而"注入决策"层**目前根本没有接入点** —— 情感项对"要不要注入"的影响是 0.0 个百分点（逐位相同）。

两句话读法：

- 情感项被放在了**唯一一个不产生可测效果的位置**上；
- 想把它放到"决策层"，缺的不是权重，是**接入点**（以及前置的估计器质量，见 `报告_源码回收清单 §11`）。

---

## 一、检索层：加了等于没加，加重显著变差

**口径**：`scripts/eval/`，69 条金标查询，`--embed none`（纯词法，跨机可复现），每臂一份独立库副本，查询间不互相强化（`accessChannel: diagnostic`）。

| 臂 | 命中@1 | 命中@5 | MRR | 说明 |
|---|---:|---:|---:|---|
| constant（常数基线） | 0.0% | 0.0% | 0.000 | 仪器门槛：必须 ≈0 |
| default（`WEIGHT_EMOTION=0.12`） | 71.0% | 97.1% | 0.811 | 现状 |
| `emo0`（情感项权重 0） | **72.5%** | 97.1% | **0.821** | 去掉情感 |
| `dev0`（偏离加成 0） | 72.5% | 97.1% | 0.821 | 去掉"珍贵瞬间" |
| `both`（两项都 0） | 72.5% | 97.1% | 0.821 | 与 `emo0` 逐位相同 |
| `emo100`（`WEIGHT_EMOTION=1.0`） | **46.4%** | 92.8% | 0.650 | 放大 8 倍 |

**配对精确 McNemar**：

```
default vs emo0   · 命中@1：仅前者命中 0 / 仅后者命中 1，p = 1
default vs dev0   · 命中@1：0 / 0，p = 1
default vs both   · 命中@1：0 / 1，p = 1
default vs emo100 · 命中@1：仅前者命中 17 / 仅后者命中 0，p < 0.0001
```

读法：

1. 去掉情感项只多中 1 条（69 条里），**p=1，不可判定** —— 也就是说情感项在检索层**既不帮也不害**，处于噪声底。
2. 把权重放大到 1.0，**17 条只有带情感才命中、0 条反过来**，p<0.0001 —— 这一项确实能强烈改变排序，方向是**变差**。它"有能力"却"无收益"，这正是"位置不对"的形状：一个能移动排序的项，在正确的查询上不该毫无贡献。
3. `dev0` 与 `both` 与 `emo0` 逐位相同 —— 「低相似 + 高情绪 +0.8 偏离加成」在这批查询上也一次都没兑现。

> 边界：69 条金标**参与过调参**（`consistency 0.95` / `WEIGHT_TIME 0.03` 是在这批上得到的），所以这里的绝对值不能当泛化性能；但同一批上的**臂间比较**（同查询、同库、同构建、只差一个环境变量）是有效的。

## 二、决策层：情感项对"要不要注入"的影响是 0

**口径**：`scripts/probe_injection_false_positive.mjs`，LCCC（thu-coai/CDial-GPT `toy_*`）11,365 条真实中文闲聊去重后分层抽 300 条（1–5 字 150 / 6–12 字 100 / 13–40 字 50）。这些句子与个人记忆库无关，**每一次注入都是假阳性**。

| WEIGHT_EMOTION | 1–5 字 | 6–12 字 | 13–40 字 | 合计 |
|---|---:|---:|---:|---:|
| 0.12（现状） | 30.7% | 19.0% | 16.0% | **24.3%** |
| 0 | 30.7% | 19.0% | 16.0% | **24.3%** |

**逐位相同，0 个百分点的差别。**

这不是"情感项太弱"，是结构性的：注入门槛判在 `similarity` 上（`recallForInjection` 的 `gateOf(h)`），情感只进 `computeScore` 的排序项。**排序不会改变"过不过门"**，所以情感项无论权重多少，都不影响有没有记忆被注入 —— 它只影响"进来的那几条谁排前面"。

这也解释了为什么这张表是 0：它测的正是"决策"，而情感没接在决策上。

## 三、所以该怎么放（按证据，不按直觉）

| 候选位置 | 现状 | 证据 | 判定 |
|---|---|---|---|
| ① 检索打分 | 已接（0.12 + ±10% 显著度） | 命中率不可判定（p=1）；放大为负（17:0） | **零效应，占位** |
| ② 注入决策 | **没有接入点** | 权重变化对注入率影响 0.0pp | 想放这儿得先写代码 |
| ③ 提示词状态块 | 已接（`band` + 三个裸数值） | 裸数值单模型 −0.072；具体描述 +0.100 但在第二个模型上归零 | 单模型证据，未改默认 |

**不建议做的事**（都已被数据挡过）：

- 继续调情感权重（0.12 与 0 不可区分；2.0 更差）——这是第二轮调参，`R41/R42` 已经把八个替代取值试完；
- 用"显著度重排"当情感层的存在理由 —— 它 ±10% 的上界正是为了不压过相关性，代价就是测不出收益；
- 在没有传感器（κ≥0.4）的前提下把情感搬进决策层 —— 那等于让一个 κ=0.145 的估计器决定"这条该不该说"。

**可以做的**：把情感接到**决策**上，但前提是两条同时成立（同 `报告_源码回收清单 §11.4`）：

1. 估计器过线：目标语言独立标注集上 κ ≥ 0.4；
2. 端到端效应可复现：同一效应在 ≥2 个家族模型上同号且区间不含 0。

在那之前，情感层最诚实的形态是**不参与决策、不占排序、不写假数据**——即当前默认（词表 abstain + `PSYCHE_FROM_VAD` 关）。

## 复现

```bash
# ① 检索层四臂（每臂独立库副本）
node scripts/eval/run_arms.mjs --db <bank根> --project airi \
  --arms default,emo0,"dev0:WEIGHT_DEVIATION=0","both:WEIGHT_EMOTION=0;WEIGHT_DEVIATION=0",emo100 \
  --embed none --out /tmp/arms.json

# ② 决策层（外部短句误注入率）
MEMORY_DB_DIR=<bank> CASTALIA_PROJECT=airi CHAR_ID=airi WEIGHT_EMOTION=0.12 \
  node scripts/probe_injection_false_positive.mjs
MEMORY_DB_DIR=<bank> CASTALIA_PROJECT=airi CHAR_ID=airi WEIGHT_EMOTION=0 \
  node scripts/probe_injection_false_positive.mjs
```

> ② 的两个跑必须用**同一份库副本**且**同一时间点**：本次两组都在合并后的库（general 活跃 136 条）上跑，所以逐位可比；换库后绝对值会变（合并前同一脚本给的是 39.3%），但两组之差仍应为 0。
