# 反思质量:能不能控、控在哪、实测差多少

> 2026-10-30。所有数字都是本机实测(airi / full bank),不是估计。方法见文末"复现"。

## 一句话结论

**质量可控,但可控的地方不是"更准",而是"更不像复述"。**
原提示词没让模型编造(锚定率 median 0.99、零锚定仅 0.5%),它让模型**空转**:80% 的洞察新颖度 < 0.3、88% 只引用一条来源 —— 所谓"跨库整合"多数只是把一条记忆重写一遍。
用「证据必须逐字可查 + 复述拦截 + 近重复累加引用 + 重要度改由验证器算」四道确定性闸后,同规模真实批次上:新颖度 0.155 → 0.755,跨源占比 12% → 87.5%,写入量 0.5 条/记录(配额生效)。

## 一、文献里的质量边界(为什么不能靠"再让模型自查一次")

| 来源 | 关键事实 | 对我们意味着什么 |
|---|---|---|
| ExpeL 消融(arXiv 2308.10144) | 把 Reflexion 式反思喂进洞察提取器,HotpotQA 成功率 **39.0 → 29.0**(基线 28.0),归因"编造的反思" | 反思产物必须先过**证据**闸,否则反思本身是负资产 |
| *A Lesson Is an Untested Counterfactual*(Zenodo 22798759) | 存储的"教训"含三个可分离断言(失败/归因/可迁移),**没有任何已发表评测检查第二条**;保留策略全部落在代理指标上;ExpeL 的 insight 带 importance 计数(起始 2,归零即删) | 我们原来的 `importance` 是模型自评,等于让被评者自己打分 —— 必须换成验证器信号 |
| 2026 经验库污染实验(同上引用) | 把**错误但内部自洽**的经验注入 10% 记忆库 → Pass@1 掉 **5.3 点** | 近重复/错误经验不清理,会被反复召回并放大 |
| MemGuard(arXiv 2608.21867) | 把多准则验证器的输出**持久化成生命周期元数据**(reward/confidence/label/uncertainty),用于准入、质量感知检索、冲突消解、归档 | 质量信号要落库(我们的 `metadata.quality`),不能只留在一次运行的结果里 |
| Hindsight observations 文档 | 观测=去重后的信念,带**证据原句、proof count、freshness 趋势**,新证据到达时 **refine 而非覆写** | 近重复应"累加引用"而不是新增一行;这正是我们第 3 闸 |
| A-Mem(NeurIPS 2025)批判性笔记 | 7 元组(内容/时间/关键词/标签/上下文描述/嵌入/链接),但**没有 confidence 字段、没有作用域** | 结构化字段救不了"没有可信度来源" |
| LLM-as-judge 元分析(v318) | 三个评测族内部一致性 r 分别 0.55 / 0.63 / 0.01 | 所以本文全部指标都是**确定性字符串/集合运算**,不引 LLM 裁判 |

## 二、改动前的实测分布(1,532 条真实洞察)

| 口径 | 值 | 解读 |
|---|---|---|
| 锚定率(与来源共享 bigram) | mean 0.943 / median 0.992 / 零锚定 0.5% | 没在编造 |
| 新颖度(自身 4-gram 中来源没有的占比) | mean **0.161**,80% < 0.3 | **复述**,反思没产生新信息 |
| 具体性(含数字/引号/专名) | 85.3% | 句子本身不空 |
| 近重复对(3-gram Jaccard > 0.6) | 57 对 / 99 条(6.4%) | 入库只做了 `text = ?` 完全相等 |
| 单源洞察 | **88.1%** | "跨库整合"实际没发生 |
| 长度 | median 115 字 / p90 414 | 长尾偏长 |
| 自评重要度 | 51 个取值,76% 落在 0.5–0.8 | 模型自陈,无区分度 |

**用新闸回测这 1,532 条**:593 条(38.5%)判为复述、223 条(14.6%)判为近重复,835 条通过。也就是说历史库存里约 **43% 是不该写进去的**。

## 三、四道闸(全部确定性,零额外 LLM 调用)

实现:`src/insightQuality.ts`;接入:`src/reflectAll.ts` 写入路径。

1. **evidence-in-source**:洞察必须带 `evidence`(4–60 字逐字原句),规范化后必须能在它引用的来源里找到。找不到 = 编造 → 硬拒。
2. **restatement**:新颖度 < 0.3 且没有"新增成分"(规则/决定/因果/对比/条件/最值)→ 判复述,不写。
3. **near-duplicate**:与已有洞察 3-gram Jaccard ≥ 0.7 **或** 包含度 ≥ 0.8 → 不新增,只给已有那条 `reference_count + 1`(Hindsight 的 refine-don't-overwrite)。单用 Jaccard 会漏掉"同一句话换语序"(实测 0.69)。
4. **verifier importance**:`0.5×来源重要度 + 0.2×跨源数 + 0.3×新颖度`,模型自评降级为 `metadata.quality.llmImportance` 留档。

提示词同步加了三件事:证据约束、`adds` 字段(rule/decision/causal/contrast/integration/summary)、**配额**(每条来源最多 1 条洞察,整批 ≤ 来源数/2)。配额是这次"退化成复述"的另一个直接原因:没有上限时模型倾向于一段来源写一条"摘要"。

## 四、A/B 实测(airi bank 一致副本,96 条记录,真实 LLM)

| | 改动前(历史 1,532 条) | 改动后(新跑 96 条) |
|---|---|---|
| 写入 | 每记录 0.64 条 | **0.50 条/记录**(配额生效) |
| 新颖度(写入的) | 0.155 | **0.755** |
| 跨源(≥2 来源) | 12% | **87.5%**(42/48) |
| 复述 | 38.5%(回测) | **0** |
| 近重复 | 14.6%(回测) | **0** |
| 证据可查 | 无此字段 | **48/48**,`evidenceOk` 全 true |
| 类型分布 | general 22% / user 40% / project 25% | general 23% / user 27% / project 48% |
| `adds` 分布 | — | integration 23 / causal 14 / contrast 4 / decision 3 / rule 2 / summary 2 |
| 重要度 | 模型自评(76% 挤在 0.5–0.8) | 验证器口径 mean 0.855,模型自评只高 0.111 |
| 成本/时延 | ~2.3s/批 | 96 条 8 批 ≈ 139s(同一量级) |

**质量提升没有以成本为代价**:闸是纯字符串运算,零 LLM 调用;配额反而把写入量砍了一半。

## 五、历史库存已按"保守口径"清理(2026-10-30)

全量回测会说 665 条该淘汰,但**真正执行时只删了 299 条(19.4%)** —— 因为数据可能不可再生(LobeHub 等库在重装系统时丢过原始记忆,有些洞察是唯一幸存副本)。执行口径(脚本 `scripts/prune_insights.mjs`):

| 规则 | 说明 | 拦下/保留 |
|---|---|---|
| 来源必须都还在且 `is_active=1` | 来源可检索 = 内容没丢;任一来源缺失或已软删 → 该洞察可能是最后一手,永不删 | 保留 **20** 条 |
| 没有 `metadata.sources` | 无锚点即无依据 | 保留 **10** 条 |
| 内容要能**逐字**在来源里找到(LCS ≥ 80%) | 4-gram 新颖度低但句子并不连续对应 → 不算复述,不删 | 保留 **186** 条 |
| 术数 / 命理 / 古籍引用保护 | 卦爻、八字、紫微十二宫、禄存四化、《增删卜易》《千里命稿》等 —— 用户明示"不可压缩资产" | 保留 **143** 条 |
| 近重复只删一方,且被删内容要在保留条里连续可查 | 避免"两条各有独有信息"被合并掉 | 删 **27** 条 |

结果:`reflect` 活跃洞察 **1,542 → 1,243**;每条软删都写 `metadata.prunedAt/prunedReason/prunedBy`,备份落在 `memory-banks/insight-prune-<ts>.json`(202KB,含原文与原始 metadata)。

**可逆性经过实测**:`--restore <backup>` 把 299 条全部恢复(活跃回到 1,542),再跑 `--apply` 又精确回到 1,243 —— 不是"理论上能恢复"。

清理后仍被新闸标为"复述/近重复"的 402 条,正是上面几类**故意保留**的(143 + 186 + 20 + 53 属近重复但另一条被保护或内容不连续)。

## 六、语义侧体检:该不该接语义去重?(2026-10-30 实测)

给 1,243 条洞察补上向量后(实际库里本来就有,只是来源库那一侧有问题,见下),跑了两组测量:

| 指标 | 值 | 结论 |
|---|---|---|
| 语义近重复对(cos ≥ 0.92) | **37 对** | 占 1,243 条里的极小比例 |
| 字面法(3-gram)检出的对 | 43 对 | — |
| 两者重叠 | 12 对 | — |
| **字面法漏掉的语义重复** | **25 对 = 67.6%** | 3-gram 确实只抓字面 |
| 但绝对量 | 25 对 / 1,243 条 ≈ **2%** | 与 MMR 那次同一个结论:不值得为 2% 引入嵌入依赖 |

**结论:语义去重暂不接入写入路径。** 真要接,应等语料翻倍或重复率上升后再评 —— 现在接等于给每条洞察加一次嵌入调用,换 2% 的去重收益。

### 顺带查出一个真缺陷:两成向量来自另一个嵌入空间

漂移测量时发现 47 条洞察与它引用的来源余弦 ≈ 0,而同一库里**随机两条**的均值是 0.479(bge-m3 的基线相似度)。逐条核对后确认:text 完全相同、来源向量的 KNN 自检也正常,唯一解释是**这条来源的存量向量不是当前模型产生的**(维度同为 1024,空间不同 —— 典型是 Ollama bge-m3 → 云端 bge-m3 这类"同名不同实现"的切换)。

全量审计(`scripts/audit_vector_space.mjs`,用当前模型重算同一条文本比对存量向量):

| bank | 检查行数 | 向量空间不一致 | 比例 | 处理 |
|---|---|---|---|---|
| airi | 254 | **69** | **27.2%** | 已修,复测 mismatched 0 |
| lobehub | 756 | 8 | 1.1% | 已修 |
| hermes | 1,161 | 5 | 0.4% | 已修 |
| dsh | 604 | 0 | 0% | 无需修 |
| **合计** | **2,775** | **82** | **3.0%** | 已修 82 条 |

不一致高度集中在 airi(canon/叙事类记忆)——说明那批是另一条嵌入通道写入的(旧 Ollama 侧),而 hermes/dsh 走的是当前通道。修复办法就是重新嵌入这 82 行:`--fix` 只覆盖不一致的行。airi 复测 **mismatched 0**。
影响范围:统一检索索引(用当前模型重建过)不受影响,但**分库 KNN 检索**对这 27% 的行会返回错误邻居 —— 这是静默故障,不修就会一直错。

## 七、还没做的(明确列出,不含糊)

1. **`adds=summary` 已改为一律不写**(2026-10-30,正文无决定/规则/因果即拒),历史库里的 summary 类没清理。
2. **语义去重不接**(实测只值 2%),但向量空间问题要盯:以后换嵌入 provider 必须整库重嵌,否则又是 27% 静默错配。
3. **没有 freshness 趋势**(Hindsight 的 strengthening/weakening):要做得按 source 集合随时间变化算,属于下一轮。
